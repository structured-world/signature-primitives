# Alternative-signature interoperability inputs

Generated by Bouncy Castle 1.80 using `scripts/generate-hybrid-vectors.sh`.
The generator verifies both mathematical signatures before saving each
certificate, CRL and PKCS#10 request. It captures the exact raw input passed
to each alternative ContentSigner as the corresponding preimage file.

All keys are newly generated public test keys. No private keys, deployment
identities or private application fixtures are distributed. Regeneration
produces different signatures and keys while preserving the same contract.

The native algorithm is ECDSA P-256/SHA-256; the alternative is pure ML-DSA-65
with absent parameters and empty context. Certificate extensions exercise
critical and non-critical encodings; the request uses single-valued attributes.
Rust tests independently verify the signatures and compare complete preimages.

References: ITU-T X.509 (2019) §§7.2.2, 7.10.3, 9.8; RFC9881 §§2–4;
Bouncy Castle `X509CertificateHolder.isAlternativeSignatureValid`,
`X509CRLHolder.isAlternativeSignatureValid` and
`PKCS10CertificationRequest.isAltSignatureValid` at tag `r1rv80` in
<https://github.com/bcgit/bc-java> (MIT license). Bouncy Castle is a test
oracle only, not a production dependency.
